# A Draft Variant is a candidate, not a Checkpoint

Substantive prose is derived from the selected argument architecture rather than from isolated wording prompts. A Studio-enabled draft names one exact Skeleton `sectionId`; Raven supplies the complete Skeleton plus the section purpose, Claim/Insight lineage, evidence needs, counterarguments, Task request, audience/constraint steering, and current Artifact as the contract. This keeps model work bounded to a coherent section while preserving its place in the larger reasoning flow.

When at least two configured routes succeed, they first render genuinely independent candidates: no route sees another candidate during generation. A later route then compares all successful candidates across argument integrity, evidence fidelity, originality, logical progression, clarity/compression, counterargument handling, reader value/surprise, and reasoning versus restatement. A `proceed` result triggers a separate synthesis request whose structured response must name concrete strengths from at least two distinct candidate routes and carry a route-specific exact fragment of at least two substantive words from each candidate into the final prose; winner-copy and malformed responses are rejected. A `research`, `synthesis`, or `structure` result stops prose synthesis, persists through replay and status, rejects premature re-drafting, blocks prose publication, and returns the main agent to the corresponding Raven work until the matching recovery succeeds and a later draft supersedes it.

The epistemic boundary does not change. Generated prose reads authoritatively, but three models agreeing on a sentence is not corroboration. Draft Variants, criterion assessments, and synthesized prose are classified exactly as Leads are: located candidate material, not verified evidence. They can never be cited or count toward the evidence floor, and wording joins the Artifact only through a Checkpoint whose factual and analytical propositions obey Raven's Source/Claim/Insight provenance. Model-authored output is delimiter-safe and explicitly marked as untrusted data for the main agent. Acceptance tests prove that even synthesized wording cannot satisfy grounding without a verified Source excerpt.

The route list belongs to the deployment, not to the agent. Naming a model names spend and a data path, so `draftRoutes` is the complete route universe for candidate, critique, and synthesis calls. An unconfigured route is refused rather than quietly substituted. Fewer than two successful candidates produce an explicit single-model or main-agent path; an empty list never silently calls the session model. This preserves basic Raven usability without bypassing deployment authorization.

Direct `ctx.llm.stream` calls remain preferable to subagents: every stage is a bounded text transformation with no tools, session persistence, or worker lifecycle. The adapter gives exact `(provider, model)` control, inspects terminal `finish` failures, and races whole stream consumption against a per-call deadline so a non-yielding adapter cannot hang the Task. Candidate calls run concurrently; critique and synthesis try successful routes serially so one failed attempt does not discard already-paid-for candidates. Caller cancellation remains cancellation.

Only bounded provenance is persisted: selected section and revision bindings, requested route outcomes and character counts, execution path, unresolved recovery, comparison recommendation/route, synthesis route, and validated contributing variant routes. Candidate, critique, and synthesized text remain transient so unadopted material cannot ride durable Task state as though it had been accepted. Required refinement context is never silently sliced, and truncation metadata remains visible. Returned candidates and synthesis use the Task's Prose Layout.
